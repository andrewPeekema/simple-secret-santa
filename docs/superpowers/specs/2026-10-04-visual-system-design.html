Visual System

Design spec · 2026-10-04 · Simple Secret Santa
Target: css/styles.css (rewritten), index.html, js/ui/setup.js, js/ui/reveal.js, js/ui/wishlist.js, js/ui/dom.js, js/main.js (the window shim only), README.md, two new guard tests under test/
Visual reference: docs/superpowers/brainstorm/2026-10-04-visual-system-mockup.html (approved 2026-10-04). Where this document and the mockup differ, this document wins.

Status: design approved in chat 2026-10-04 after four rounds of mockup edits; critic findings 1–10 and the five unstated assumptions applied the same day. Classified bounded at the outset; upgraded to a written spec because the approved design restructures two flows and touches every screen, which is more than five tasks. Rulings recorded in §0: direction A (tighten what exists); a three-step type scale; section titles in the serif at body size; 6 px radius; the five original star colours kept; no italics; one container level per screen; results and the wishlist link each replace the form that produced them.

Requirements

Decomposes

  • REQ-SSS-0009 — usable on a phone screen at least as narrow as 412 CSS px.
    • REQ-SSS-0009.1 Every screen in §5 shall fit a 412 px viewport with no horizontal scrolling.
    • REQ-SSS-0009.2 Every button, text link and text input shall present a tap target at least 42 px tall.
    • REQ-SSS-0009.3 An exclusion row shall wrap its two selects onto their own lines below 480 px, as today.
  • REQ-SSS-0010 — one fixed colour theme regardless of device preference.
    • REQ-SSS-0010.1 Every colour shall be defined once, as a custom property on :root in css/styles.css (§2).
    • REQ-SSS-0010.2 No colour literal (hex, rgb(), rgba(), named colour) shall appear outside that :root block — not elsewhere in the stylesheet, not in index.html, not in any JS template.
    • REQ-SSS-0010.3 The stylesheet shall contain no prefers-color-scheme rule.
  • REQ-SSS-0007 — the README and the UI claim no more wishlist protection than the code delivers.
    • REQ-SSS-0007.1 Every user-facing string about wishlists that this spec adds or changes shall be one of those in §4, and each shall describe the password gate and nothing stronger. Strings this spec keeps were judged honest by the 2026-09-19 wording plan and are not re-opened.

Consulted, not changed: REQ-SSS-0001 (each link reveals only its own assignment — the reveal screen still shows one giver and one receiver); REQ-SSS-0002 (exclusions — the form keeps the exclusion rows and their behaviour); REQ-SSS-0003 and REQ-SSS-0006 (the wishlist password still appears on the Santa's reveal screen, §5.3); REQ-SSS-0005 (no build step — plain CSS custom properties, no preprocessor, no bundler); REQ-SSS-0008 (the giver's name still appears on the reveal screen, as the greeting in §5.3).

1. Facts

From a full read of the styling surface on 2026-10-04 (Explore audits; every file read in full).

  • About 15 rendered font sizes from 23 font-size declarations in the stylesheet (in rem, px and em) plus 15 inline — 13 in JS templates, 2 in index.html. Seven letter-spacing values. DM Sans 600 loaded, unused; a faked sans italic on the reveal screen.
  • The single h2 (19.2 px) is barely larger than h3 (17.6 px); h3 has four looks. Headings are faked with <strong>, <strong><br><br> and an all-inline uppercase label. The recipient's name is a bold gold div.
  • Title Case headings, ALL CAPS buttons (via text-transform), sentence-case labels; "How It Works" and "How it works" both appear.
  • Three greens, hard-coded gold / silver / ice-blue, a pink glow used only in two box-shadows, warning = error red, 3 unused and 5 duplicate tokens.
  • Seven button variants, ~11 box kinds, 30 inline style= attributes, one CSS rule that selects on inline-style text (div[style*="background: var(--bg-tertiary)"] strong) and seven !important declarations across four rules.
  • Bug. copyToClipboard (js/ui/dom.js:27-34) sets an inline background #38a169 and restores originalBg || '#48bb78'; originalBg is always empty, so every copy button is permanently off-palette green after its first click.
  • Tests under test/ import nothing from js/ui/ or js/main.js. test/legacy-removed.test.js does read js/main.js and js/ui/wishlist.js as text and asserts on strings (§7).
  • JS depends on these selectors; none may be renamed: ids mainContainer, setupSection, peopleList, exclusionsList, results, successBanner, copyAllBtn, linksList, revealSection, hintsSection, viewHintsSection, hintsText, hintLengthWarning, hintLinkDisplay, hint-link-input, passwordInput, decodedHints; classes person-name, exclusion-row, person1-select, person2-select.
  • index.html:83-93 carries a comment warning that the nesting of #revealSection, #hintsSection and #viewHintsSection relative to #mainContainer must not be changed. This spec does not change it (§7).

6. The copy button (bug fix)

copyToClipboard(text, button) in js/ui/dom.js no longer writes button.style.background. It saves button.textContent, sets it to "✓ Copied", adds the class is-copied, and after 2000 ms restores the text and removes the class. CSS: .btn.is-copied sets color: var(--text-2) and, for .btn--secondary, border-color: var(--line). The #38a169 and #48bb78 literals are deleted. The clipboard fallback and the failure alert are unchanged.

7. Constraints on the implementation

  • Inline styles. After this change the only style= attributes anywhere in index.html or the JS templates are style="display: none" on containers that JS shows and hides. Every other inline style becomes a class in css/styles.css. The selector div[style*="background: var(--bg-tertiary)"] strong and every !important are deleted.
  • Selectors. No id or class listed in §1 is renamed or removed. New classes may be added freely.
  • Nesting. The positions of #mainContainer, #revealSection, #hintsSection and #viewHintsSection in index.html, and the show/hide calls that target them, are unchanged. The comment at index.html:83-93 stays. The one structural move is #results out of #setupSection (§5.2); the implementer counts the opening and closing divs of #mainContainer before and after and keeps the three overlay sections where they are.
  • Text-reading tests. test/legacy-removed.test.js reads js/main.js and js/ui/wishlist.js as text. js/main.js must not contain hash.startsWith('hints-'); js/ui/wishlist.js must not contain text.startsWith('VALID:'), .isLegacy or enteredPassword.startsWith('0'), and must contain enteredPassword.length === 5 exactly once. Template edits must respect this.
  • No logic changes beyond §5.2, §5.5, §5.6 show/hide and §6. Encoding, assignment, validation, hashing and the hint codec are untouched.
  • Escaping. Every interpolated name or URL continues to pass through escapeHtml; the two value="…" uses stay as they are (URLs contain no quotes).
  • Mobile. Below 480 px: card padding --s-4, body padding --s-3 --s-2, exclusion rows wrap with each select full width and the ↔ hidden, as today.

8. Tests and verification

8.1 Guard tests (new, node:test, same style as test/legacy-removed.test.js)

  • test/styles.test.js reads css/styles.css as text and asserts: (a) every match of /#[0-9a-f]{3,8}\b|rgba?\(/i lies inside the first :root { … } block (REQ-SSS-0010.2); (b) the text contains no prefers-color-scheme (REQ-SSS-0010.3); (c) no !important; (d) no text-transform; (e) no font-style: italic; (f) every font-size: value is one of var(--t-heading), var(--t-body), var(--t-note) or inherit.
  • test/templates.test.js reads index.html and every file under js/ui/ as text and asserts: (a) every style="…" attribute is exactly display: none (allowing display:none and a trailing semicolon); (b) no colour literal as in 8.1(a); (c) index.html loads only the two font weights of §3.1; (d) none of the removed class names of §3.4 appears as a class token — i.e. inside a class="…" attribute value or a className = '…' assignment, split on whitespace; prose, comments, variable names and console.error are not matched.

The existing suite (40 tests at f1ed2c0) stays green.

9. Scope

In: everything above; the README item 4 wording; deleting dead CSS.

Out: any change to link encoding, assignment, validation, or the wishlist codec; dark/light switching (REQ-SSS-0010 forbids it); a custom domain; sharing UX (sub-project 3 of the restart spec, still deferred); replacing inline onclick handlers with listeners (the restart spec deliberately left them; this spec keeps them and only changes their button classes).
