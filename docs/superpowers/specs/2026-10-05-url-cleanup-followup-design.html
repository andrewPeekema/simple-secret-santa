2. Shop lookup and the Best Buy row (REQ-SSS-0003.9)

2.1 Lookup

A host may now have more than one row, so the lookup is "first row whose host matches and whose ID is found in the written path":

const h = parsed.hostname;
const onShop = SHOPS.some(row => row.host(h));
for (const row of SHOPS) {
  if (!row.host(h)) continue;
  const hit = discardableTail(url, row.id);        // { id, tail } or null
  if (hit) return parsed.origin + row.path(hit.id) + keptQuery(url, row.keep);
}
return stripTracking(url, onShop ? shopJunk(h) : null);   // the generic rule

discardableTail runs the ID pattern once, on the written path (the URL up to the first ? or #), and returns { id: m[1], tail } when the tail is empty or the rest of a URL with nothing foreign in it, else null. parsed.pathname is no longer matched (review finding 6). The written path is authoritative; .. segments are not resolved, consistent with the earlier spec's "no normalisation". Row order within a host decides ties; today no two rows of one host can both match.

5. Text-level fixes (REQ-SSS-0003.12, 0003.13)

  1. Glued ASCII (finding 1). TRAILING gains * _ ~; ] is peeled like ), only while the body holds more ] than [. Peeled characters are restored after the cleaned URL as today.
  2. Apostrophes (finding 2). URL_RUN becomes /https?:\/\/[^\s<>"]+/gi: an apostrophe no longer ends a run. A trailing ' is still peeled (it is in TRAILING), so 'https://…?utm_source=1' keeps its quotes.
  3. Emptied query (finding 3). In stripTracking, after removing pairs: if every remaining pair is the empty string, the query goes entirely (no ?); otherwise the remaining pairs are re-joined as written, empties included (?a=1&&utm_source=2 → ?a=1&).
  4. Non-ASCII punctuation (finding 4). TRAILING gains 。 、 ！ ？ ， ： ； ） 」 』 ’ ”. A run ending in text (…?tag=x。谢谢) is still glued and still left alone (GLUED 231).
  5. Semicolons (finding 5). A pair whose text contains ; is never removed, whatever its name (it joins the foreign(pair) keep condition).
  6. One match (finding 6). §2.1.

Unchanged: URL_CHARS, foreign, the GLUED policy (text glued to a URL means the URL is left as written), keep handling, idempotence (tidyUrl(tidyUrl(u)) === tidyUrl(u) must still hold for every case in §7).

6. shortenLink (REQ-SSS-0003.14)

After trimming and before new URL: if the trimmed input contains any whitespace (/\s/), return { state: 'notUrl' }. Two links, or a link followed by words, therefore show "Paste one full link, starting with http." instead of the false "already as short as it gets". Nothing else in shorten.js or in wishlist.js changes.
