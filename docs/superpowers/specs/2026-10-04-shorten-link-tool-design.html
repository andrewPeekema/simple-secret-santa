Status: design approved in chat 2026-10-04 after three prototype rounds. The previous branch made shop-link shortening automatic at Generate time. The user wants it opt-in instead: a collapsible section under the wishlist box where the participant pastes one link and copies back the short one, and the wishlist text is encoded exactly as typed. The seven /code-review findings against js/urls.js from the same day are deliberately left for a follow-up (§9); this spec changes who calls the function, not what it does.

Requirements

Decomposes

REQ-SSS-0003 — a participant can create an optional wishlist from the assignment link that only their Santa can open. Sub-IDs below are local to this spec; the earlier spec's 0003.1–0003.3 are cited with its filename.

  • REQ-SSS-0003.1 The wishlist link shall be generated from the textarea's text, trimmed, with no URL rewritten and no character of the text changed before it enters encodeHints.
  • REQ-SSS-0003.2 The wishlist create screen shall offer a section titled "Shorten a link", below the Generate button, that is closed when the screen opens and opens only when the participant taps its title.
  • REQ-SSS-0003.3 The section shall take one link in a single-line field and, as the participant types or pastes, show tidyUrl(input) in a read-only field with a copy button whenever that result differs from the input.
  • REQ-SSS-0003.4 When the field is empty the section shall show no result and no note; when the input is not an http(s) URL, or tidyUrl returns it unchanged, the section shall show the matching note from §5 and no result.
  • REQ-SSS-0003.5 The section shall neither read nor write the wishlist textarea, and the Generate flow shall not read the section.

REQ-SSS-0007 — the README and the UI claim no more protection than the code delivers.

  • REQ-SSS-0007.1 The section's description shall name exactly the six shop hosts of the earlier spec's §2.2 table and shall describe every other link as losing only its tracking tags; the README sentence shall make the same claim and no stronger one.

Consulted, not changed: REQ-SSS-0004 (no fetch; tidyUrl is string work); REQ-SSS-0005 (a plain ES module, no dependency, no build step); REQ-SSS-0009 (the section is one column of full-width .in fields and a block button, the same shapes the screen already uses at 412 px); REQ-SSS-0010 (no new colour token; every new rule uses existing variables); REQ-SSS-0006 and REQ-SSS-0011 (password and link format untouched).

3. Module js/shorten.js (REQ-SSS-0003.3, 0003.4)

A pure module directly under js/, beside urls.js, so the state logic is unit-tested in node without a DOM (wishlist.js touches window at import time and cannot be imported by a test).

import { tidyUrl } from './urls.js';

// string -> { state: 'empty' } | { state: 'notUrl' } | { state: 'unchanged' } | { state: 'short', url: string }
export function shortenLink(input)
  • Trim the input. Empty → { state: 'empty' }.
  • Not an http(s) URL → { state: 'notUrl' }. "Is an http(s) URL" means new URL(trimmed) does not throw and protocol is http: or https:. No scheme is guessed: www.amazon.com/dp/B0ABCDEFGH is notUrl.
  • tidyUrl(trimmed) === trimmed → { state: 'unchanged' }.
  • Otherwise { state: 'short', url: tidyUrl(trimmed) }.
  • Never throws. It is the only caller of tidyUrl in js/ui or js/shorten.js; tidyUrls keeps its export and its tests but has no caller in the app.

4. The section (REQ-SSS-0003.2, 0003.3, 0003.4, 0003.5)

4.1 Markup

Inserted into the showCreateHints template between the Generate button (line 33) and the Back <p class="nav"> (line 34), inside #hintsForm so it hides with the form on the link-ready screen and comes back with Back, state intact:

<hr class="sep">
<details class="tool">
    <summary><h2 class="section-title">Shorten a link <span class="optional">(optional)</span></h2></summary>
    <p class="note mt-2">Paste a link to get a shorter one for your wishlist. Amazon, Etsy, eBay, Walmart, Target and Best Buy links are cut down to just the product; other links only lose their tracking tags.</p>
    <input type="url" id="shortenIn" class="in mt-3" placeholder="https://www.amazon.com/…" autocomplete="off" spellcheck="false">
    <div id="shortenResult" style="display: none;">
        <input type="text" id="shortenOut" class="in in--url mt-3" readonly>
        <button class="btn btn--secondary btn--block mt-3" onclick="copyToClipboard(document.getElementById('shortenOut').value, this)">Copy short link</button>
    </div>
    <p id="shortenNote" class="note mt-2" style="display: none;"></p>
</details>
  • No open attribute: closed on every render (REQ-SSS-0003.2). showCreateHints re-renders the template each time it is entered from the reveal screen, so re-entry gives a closed, empty section; Back from the link-ready screen only un-hides the form, so the section keeps whatever the participant had in it.
  • The title follows index.html:55 exactly (an h2.section-title with span.optional and parentheses). It is the only h2 on the screen; h1, h2 { margin: 0 } keeps it on the summary line.
  • type="url" gives phones a URL keyboard; there is no enclosing <form>, so no browser validation UI appears. #shortenOut is a readonly text input in the mono in--url style, the same as the hint-link field.
  • Every class token is already styled except tool, which §4.3 styles; both inline styles are display: none; no colour literal; no removed class (§1 guard rules).

4.2 Wiring

In showCreateHints, after the existing #hintsText listener, attach an input listener to #shortenIn that calls a module-level function renderShortener() (not exported; it lives in wishlist.js above showCreateHints). renderShortener reads #shortenIn.value, calls shortenLink, and sets the DOM from the state and nothing else:

  • Values go through .value and .textContent, never innerHTML, so no escaping question arises.
  • renderShortener and the listener reference shortenIn, shortenOut, shortenResult and shortenNote only — never hintsText (REQ-SSS-0003.5). Copy uses copyToClipboard through the existing window shim, unchanged.

6.1 test/shorten.test.js (new)

  • '', ' ' → empty.
  • 'socks', 'www.amazon.com/dp/B0ABCDEFGH', 'mailto:a@b.c', 'https://' → notUrl.

7. Manual check

The director runs it on the VM copy after merge, on a phone-width window. Open an assignment link, Create your wishlist. Expect: the screen shows the textarea, the note, Generate, a rule, a closed "Shorten a link (optional)" line with a chevron, and Back. Tap the title: it opens with the description and an empty field, nothing else. Paste a long Amazon URL: the short link appears in a mono field with "Copy short link"; press it, see "✓ Copied", paste into the wishlist box. Replace the field with socks: the result goes, the http note shows. Replace with https://a.co/d/abc123: the "already as short" note shows. Clear it: nothing shows. Type a long Amazon URL into the wishlist box itself and Generate: the link-ready screen has no "Shortened" note; Back shows the text exactly as typed; opening the wishlist link with the password shows the long URL verbatim.
