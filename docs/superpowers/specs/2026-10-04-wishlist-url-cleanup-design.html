Wishlist URL Cleanup

Design spec · 2026-10-04 · Simple Secret Santa
Target: new js/urls.js, js/ui/wishlist.js (generateHintLink only), new test/urls.test.js, one new guard test, README.md (one sentence).
Companion: docs/superpowers/specs/2026-10-04-visual-system-design.html §5.5 describes the wishlist create and link-ready screens this spec adds one line to. Where the two differ about that line, this document wins.

Status: design approved in chat 2026-10-04. Research question: how can large wishlists make shorter links? Five ideas were put to the user; the ruling was "do idea 3 (clean up shop URLs), then spike idea 1 (a denser Unicode alphabet)". Idea 3 is this spec. Classified bounded; written up as a spec because the user chose to hand it to a lead. The spike is out of scope here (§8).

Requirements

Decomposes

  • REQ-SSS-0003 — a participant can create an optional wishlist from the assignment link that only their Santa can open.
    • REQ-SSS-0003.1 When the wishlist link is generated, every http(s) URL in the text that matches a rule in §2.2 shall be replaced by that rule's short form before the text is encoded.
    • REQ-SSS-0003.2 The owner shall see the cleaned text: the textarea is rewritten with it, and the link-ready screen states how many links were shortened (§3).
    • REQ-SSS-0003.3 A URL that no rule changes, and all text that is not a URL, shall be carried through unchanged, character for character.

Consulted, not changed: REQ-SSS-0004 (no participant data to any server — the cleanup is string work in the browser; no URL is fetched, so short links such as a.co and amzn.to cannot be expanded and are left alone); REQ-SSS-0005 (no build step — a plain ES module, no dependency); REQ-SSS-0007 (the one new UI string claims nothing about protection, §4); REQ-SSS-0006 and REQ-SSS-0011 (the password and the link format #h-<name>.<ciphertext> are untouched; only the plaintext changes before it enters the existing codec).

2. Module js/urls.js (REQ-SSS-0003.1, 0003.3)

Pure functions, no DOM, no imports. Both exported.

2.1 API

export function tidyUrl(url)   // string -> string: the short form, or `url` unchanged
export function tidyUrls(text) // string -> { text: string, shortened: number }
  • tidyUrl parses with new URL(url). If parsing throws, or the protocol is not http:/https:, it returns the input unchanged. It never throws.
  • It returns a string different from the input only when a rule actually removed or replaced something; a URL already in short form comes back identical (tidyUrl(tidyUrl(u)) === tidyUrl(u)).
  • tidyUrls finds every maximal run matching /https?:\/\/[^\s<>"']+/g, peels trailing sentence punctuation off the run before cleaning and puts it back after (characters . , ; : ! ? ' ", and a trailing ) only when the run contains no (), passes the rest to tidyUrl, and counts a URL as shortened when the result differs from the input. Everything outside the matched runs is copied verbatim.

2.2 Rules

Host matching is case-insensitive on url.hostname. "Any TLD" means the hostname matches /(^|\.)amazon\.[a-z.]{2,}$/ (likewise ebay); this excludes media-amazon.com and similar. The ID pattern is applied to url.pathname. A shop rule whose ID pattern does not match falls through to the generic rule. A shop rule that matches produces origin + path with no query string and no fragment.

HostPath pattern (first match)Short form
Amazon, any TLD/(?:dp|gp\/product|gp\/aw\/d)\/([A-Z0-9]{10})(?![A-Za-z0-9])<origin>/dp/<ASIN>
etsy.com, www.etsy.com/listing/(\d+) (a locale segment such as /uk before it is allowed and dropped)<origin>/listing/<id>
eBay, any TLD/itm/(?:[^/]+/)?(\d{9,15})<origin>/itm/<id>
walmart.com, www.walmart.com/ip/(?:[^/]+/)?(\d+)<origin>/ip/<id>
target.com, www.target.com/p/(?:[^/]+/)?-/A-(\d+)<origin>/p/-/A-<id>
bestbuy.com, www.bestbuy.com/site/(?:[^/]+/)?(\d+)\.p<origin>/site/<sku>.p
Every other host, and a shop host whose pattern did not match—Same URL with these query parameters removed: any name starting utm_, and exactly ref, ref_, tag, fbclid, gclid, msclkid, mc_cid, mc_eid, _ga, igshid. All other parameters keep their order and values; an emptied query drops its ?; the fragment is kept.

Not done, deliberately: no www. or trailing-slash normalisation on generic hosts; no scheme change; no percent-decoding; no expansion of short links; no rule for a host not in the table even when its URL looks like a product page. ASIN is matched upper-case only, as Amazon issues them.

3. The generate flow (REQ-SSS-0003.2)

In generateHintLink(), after the empty-text alert and before the 2000-character confirm:

  1. const tidy = tidyUrls(hintsText);
  2. If tidy.shortened > 0: set #hintsText.value = tidy.text and dispatch new Event('input') on it so the 1500-character warning (§1) re-evaluates against the cleaned length. (The template string in showCreateHints is not touched.)
  3. Use tidy.text for the 2000-character confirm, for encodeHints, and for nothing else; the password derivation and URL assembly are unchanged.
  4. In the link-ready template, immediately after the existing "Share it with the group…" note, add <p class="note mt-3">Shortened N shop links.</p> only when tidy.shortened > 0 ("Shortened 1 shop link." for one). Nothing is added when nothing was shortened.

Import: import { tidyUrls } from '../urls.js'; beside the existing imports. Back from the link-ready screen keeps hiding/showing the form as today, so it shows the cleaned text; no state is saved.

5. Tests

Runner: node --test via npm test; no dependencies, no DOM. The suite is 78/78 at main f2e601c and must stay green.

5.1 test/urls.test.js (new)

  • One case per shop row in §2.2 using a realistic long URL (slug, ref=, ?th=1&psc=1, utm_) → the exact short form; include amazon.co.uk and an Etsy URL with a /uk/ locale segment.
  • Generic host: https://shop.example.com/item?variant=3&utm_source=x&fbclid=y#reviews → https://shop.example.com/item?variant=3#reviews.
  • Unchanged: an unknown host with no tracking params; https://a.co/d/abc123; an Amazon URL with no ASIN in its path but a tracking param (loses only the param); https://m.media-amazon.com/images/I/x.jpg; a mailto: or ftp:// URL; the string https:// alone; a URL already in short form (identity).
  • tidyUrls: text with two shop URLs and prose → both replaced, prose byte-identical, shortened === 2; a URL followed by . and one wrapped in (…) keep their punctuation outside the URL; text with no URL → same text, shortened === 0; a Wikipedia-style URL ending in ) with a ( inside keeps the ).

5.2 Guard (new test in test/templates.test.js or a new file)

Reads js/ui/wishlist.js as text and asserts it imports tidyUrls from '../urls.js' and that the call tidyUrls( appears before encodeHints( inside generateHintLink. There are no DOM tests in this repo; this pins the wiring the way the other guard tests do.

5.3 Existing suites

test/templates.test.js scans js/ui/wishlist.js: the new <p> uses only note and mt-3, no inline style, no colour. test/legacy-removed.test.js strings (§1) must remain exactly as they are. test/golden.test.js, test/format.test.js and test/compress.test.js are untouched: the codec does not change.

6. Manual check

The director runs it on the VM copy after merge: open an assignment link, create a wishlist containing one long Amazon URL followed by a full stop, one Etsy URL in parentheses and one unknown-host URL with ?size=M; Generate. Expect: the textarea shows the two short forms with the punctuation intact and the unknown URL unchanged; the link-ready screen shows "Shortened 2 shop links."; Back shows the cleaned text; opening the wishlist link with the password shows the cleaned text.

7. Constraints on the implementation

  • No dependency, no build step, no fetch (REQ-SSS-0004, 0005). js/urls.js lives directly under js/, not js/ui/.
  • No change to js/format.js, js/compress.js, js/secret.js, js/main.js, css/styles.css or index.html. No new CSS class, no inline style other than display: none.
  • Only generateHintLink changes in wishlist.js; inline onclick handlers stay as they are.
  • Commit per task on branch wishlist-url-cleanup; do not push; do not merge to main — the director does that on the user's ruling.

8. Scope

In: §§2-5 and the README sentence.

Out: the base2048/base32768 alphabet spike (idea 1, separate work); dictionary compression; a shorter domain or plaintext owner name; cleaning on paste; expanding short links; any change to the 1500/2000-character thresholds or their wording.
